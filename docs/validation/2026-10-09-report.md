执行与源码复核：Codex；未经过独立人工双人标注或上游维护者确认。

## 结论

本轮完成 5 个固定版本开源项目的离线验证。生产包目录覆盖 **965 个 Python 文件、192,774 行 Python 文本**；包含测试、脚本与示例的完整仓库覆盖 **3,059 个文件、557,478 行**。两种扫描范围重叠，不能相加。

生产包扫描产生 **50 条告警**，均与当前语法规则匹配：47 条通配导入、2 条 eval 调用、1 条裸 except。复核表明大量告警属于有意设计，**本轮没有确认新的生产缺陷或安全漏洞**。50 条是告警数量，不能写成“发现 50 个 Bug”。

现有工具具备可重复的规则扫描、结构化报告和基线过滤能力；其上下文判断、规则覆盖面和基线定位仍有限。本轮为真实项目源码离线测评，**不是线上生产环境压测、实际用户效果实验或完整安全审计**。

## 1. 样本与方法

使用历史固定发布版构建可复现样本，不声称它们是当前最新版。目标项目仅下载、读取和 AST 解析，没有安装目标项目依赖，也没有导入或执行目标源码。

| 项目及源码链接 | 发布标签 | Git commit | 生产包扫描入口 |
|---|---|---|---|
| [requests](https://github.com/psf/requests/tree/b25c87d7cb8d6a18a37fa12442b5f883f9e41741) | v2.32.5 | b25c87d7cb8d6a18a37fa12442b5f883f9e41741 | src/requests |
| [flask](https://github.com/pallets/flask/tree/2c1b30d0503cfb064f1cb252e6614a06915a362a) | 3.1.2 | 2c1b30d0503cfb064f1cb252e6614a06915a362a | src/flask |
| [click](https://github.com/pallets/click/tree/00fadb8904387158ce6e9aa1573be770446895c1) | 8.3.0 | 00fadb8904387158ce6e9aa1573be770446895c1 | src/click |
| [httpx](https://github.com/encode/httpx/tree/26d48e0634e6ee9cdc0533996db289ce4b430177) | 0.28.1 | 26d48e0634e6ee9cdc0533996db289ce4b430177 | httpx |
| [django](https://github.com/django/django/tree/3cff3209e35a560f94801d428cf7f2a3ecb2a051) | 5.2.7 | 3cff3209e35a560f94801d428cf7f2a3ecb2a051 | django |

- 生产包目录分别扫描 6 次：首次观测单列，后续 5 次独立进程取中位数和范围；所有正式计时顺序执行。
- 每次计时包括 Python 启动、依赖导入、图构建、扫描、规则检查、报告序列化及进程退出。不是纯 AST 算法耗时。
- 没有清空操作系统文件缓存；首次观测也不能当作严格冷启动。结果来自单台开发机，不外推到其他机器。
- 完整仓库每个扫描 1 次，用于验证规模与范围差异，没有足够样本计算稳定的分位数。
- 行数为 Python 文件的**物理文本行数**，包含空行、注释和文档字符串，不是可执行代码行数。
- 文件数与独立 os.walk 清单核对；源码快照在扫描前后校验，Git 工作区均保持干净。
- 10 月 9 日离线验证的实际扫描使用 --no-llm。另有一次显式清空密钥的默认模式调用，用于验证缺失密钥时的降级。10 月 10 日真实 LLM 补测另列于第 7 节。
- 未构建真实项目的完整缺陷真值集，因此不报告生产准确率、召回率或 F1。

执行环境：Windows 11，Python 3.13.10，28 个逻辑 CPU（本机报告），langgraph 1.2.12、openai 3.19.0、python-dotenv 1.2.3。扫描逻辑当前为顺序执行，CPU 数量不代表使用了 28 路并行。默认 python 指向 3.10，本轮明确使用 D:/python/python.exe。

## 4. 50 条生产包告警的源码复核

| 告警类别 | 数量 | 复核结论 |
|---|---:|---|
| R004 通配导入 | 47 | 全部位于包 __init__.py；用于公共 API 重导出，不能据此判定缺陷 |
| R003 eval | 2 | Flask 本地 Shell 启动脚本、Django 本地迁移交互；未证明存在不可信远程输入链 |
| R001 裸 except | 1 | Flask 捕获后立即 raise；“吞掉所有异常”的说明不符合该上下文 |
| 经本轮确认的新缺陷 | 0 | 不代表这些项目不存在缺陷，也不代表工具真实准确率为 0 |

具体证据：

1. [Flask app.py:1515](https://github.com/pallets/flask/blob/2c1b30d0503cfb064f1cb252e6614a06915a362a/src/flask/app.py#L1515)：保存异常供 finally 清理使用，随后重新抛出；机械替换为 except Exception 会改变 BaseException 路径行为。
2. [Flask cli.py:1031](https://github.com/pallets/flask/blob/2c1b30d0503cfb064f1cb252e6614a06915a362a/src/flask/cli.py#L1031)：执行用户本机 PYTHONSTARTUP 脚本，是交互式 Shell 功能。
3. [Django questioner.py:168](https://github.com/django/django/blob/3cff3209e35a560f94801d428cf7f2a3ecb2a051/django/db/migrations/questioner.py#L168)：求值迁移交互输入的 Python 表达式。
4. [HTTPX __init__.py](https://github.com/encode/httpx/blob/26d48e0634e6ee9cdc0533996db289ce4b430177/httpx/__init__.py)：集中导出客户端等 API，并定义 __all__。
5. [Django models/__init__.py](https://github.com/django/django/blob/3cff3209e35a560f94801d428cf7f2a3ecb2a051/django/db/models/__init__.py)：重导出 ORM 接口，命中行有 NOQA 标记。

逐条记录见 [source-review.csv](../../benchmarks/results/2026-10-09/source-review.csv)；包含固定 commit 链接、行号、片段和判断理由。规则匹配正确与业务上需要修复是不同的指标。本轮复核由 Codex 完成，未宣称为人工专家真值标注。

## 5. 已知答案的规则与边界用例

**规则约定内对照集：26/26 个文件符合预期。** 预期 16 条告警，实际检出 16 条，额外告警 0、遗漏 0。包含裸 except、显式异常、可变字面量默认参数、普通与异步函数、直接 eval、对象同名方法、通配导入、字符串中的伪代码、语法错误与 UTF-8 读取失败等。

这是根据当前规则范围构造的小型合成集，用于验证实现一致性；不能转写成“生产检出率或准确率 100%”。非 UTF-8 文件在约定集中预期得到 E000，同时在扩展探针中揭示通用源码兼容性不足，两种期望刻意不同。

另设 **8 个针对已知边界的探针**，全部未达到更广的语义目标。这些是定向挑战用例，不能据其占比估计真实项目发生频率：

| 探针 | 实际结果 | 能力边界 |
|---|---|---|
| list() 作为默认值 | 未告警 | R002 只匹配字面量 |
| set() 作为默认值 | 未告警 | 同上 |
| 元组中嵌套可变列表默认值 | 未告警 | 未递归判断可变性 |
| eval 赋值给别名后调用 | 未告警 | 无别名追踪 |
| builtins.eval 调用 | 未告警 | 只匹配 ast.Name |
| 普通参数命名为 eval 并调用 | 告警 | 无名称绑定分析 |
| except 后清理并立即 raise | 提示吞掉异常 | 提示语缺乏控制流上下文 |
| 合法 Latin-1 编码声明源码 | E000 | 读取硬编码 UTF-8，未遵循编码声明 |

完整输入与预期见 [cases.json](../../benchmarks/results/2026-10-09/cases.json)，结果见 [contract.json](../../benchmarks/results/2026-10-09/contract.json)、[boundary.json](../../benchmarks/results/2026-10-09/boundary.json)。

## 6. CI 基线实验

| 实验 | 结果 |
|---|---|
| 5 个原始生产包保存基线后立即复扫 | 50/50 条旧告警被过滤，5/5 次返回 0 |
| Django 派生副本新增 4 类规则问题 | 4/4 条新增问题被检出，原有 32 条仍被过滤 |
| 给 Django 原告警所在的 12 个文件各加一行注释 | 19/32 条旧告警被重新报告，返回 1；其余 13 条因规则和旧行号重叠被过滤 |
| 未配置密钥时按默认模式扫描 Django | 保留全部 32 条规则告警，LLM 结果为空，进程正常结束 |

行号变化实验没有引入新的问题，却产生 **19 条重复告警（旧告警的 59.4%）**。当前基线键是 rule_id + 相对路径 + 行号；连续同规则告警还可能因行号重叠被错误对应。基线适合初步接入，但对代码移动不稳健。

以上行为检查及重复扫描等共 54 项自动断言通过，见 [checks.json](../../benchmarks/results/2026-10-09/checks.json)。这里的“通过”指符合本次检查断言，不代表已消除上述能力局限。

## 8. 现有测试与环境问题

现有 test_cli.py、test_rules.py、test_llm_node.py：**25 passed in 4.10s**。命令明确选择这三个文件，禁用 pytest 缓存和外部自动加载插件。

首次沙箱测试失败在 pytest 临时目录准备阶段。最小复现表明：本环境创建的 mode=0700 目录在沙箱中不可读取，普通 mode=0777 目录可读取。改为正常 Windows 权限执行相同测试后通过；产品代码未为此做修改。失败与成功日志均保留，避免把环境故障隐藏成“从未失败”。
